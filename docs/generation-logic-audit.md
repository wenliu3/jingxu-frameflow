# 视频生成逻辑整改（2026-10-04）

这是早期生成链路整改的历史记录，包含当时的界面与验证结果。当前参数默认值、画幅控制、视频参考和续拍行为以 [README](../README.md)、[画布指南](storyboard-canvas.md) 和 [视频参考与续拍](video-continuation-plan.md) 为准。

本轮核查素材选择、提示词编排、分镜参数、服务切换、任务执行、视频下载及生成记录，前后端一起整改。没有调用真实生成服务，也没有修改现有作品、服务地址和密钥。

## 默认值和单镜覆盖

两个分辨率入口控制同一个像素预算，但作用范围不同：

| 入口 | 规则 |
| --- | --- |
| 服务设置：默认分辨率 | 为未指定数值的 ComfyUI 任务提供默认值 |
| 分镜设置：本镜分辨率 | 默认跟随服务；明确选择数值只覆盖当前镜头 |
| 素材工坊旧生成表单：本次分辨率 | 只影响本次请求，不再修改全局配置 |

新建分镜不再硬编码 0.5MP。选择「跟随服务默认」时，在提交生成请求时读取默认值；任务提交后固定这个值。已有分镜明确保存过的数值保持不变，可主动切回继承。合法的旧自定义预算继续显示。

去掉错误的 720p/1080p 档位名称。MP 是总像素预算，实际宽高取决于输入图片、工作流及尺寸对齐，不能把 0.98MP 标成 1080p。删除未传入生成接口的「构图参考／视频比例」控制，避免形成无效承诺。

## 发现的问题与处理

| 原问题 | 整改结果 |
| --- | --- |
| 外接视频 API 沿用 ComfyUI 的时长、分辨率与 Ref2VA 提示词语义 | 按实际后端选择编排格式；隐藏 API 不接收的像素预算，时长只作为提示词计划节奏 |
| 切换到 API 后，被残留的 ComfyUI LoRA 配置拦住 | 生成前只检查当前后端会使用的配置；API 不再显示无关的采样提醒 |
| 音色自动写入提示词，但未真正传给视频模型 | 当前视频入口仅接受图片，不再加入虚假的音频参考；音色素材仍可管理与试听 |
| 缺失、重复或超量图片可能被静默丢弃 | 前后端在提交前明确拒绝，Ref2VA 最多九张，一镜最多一个场景；单首帧模式不允许额外图片悄悄被忽略 |
| 编排检查设定图，生成实际需要单张首帧 | 编排前按实际工作流检查同一套图片解析规则，避免无首帧时先花费文本调用 |
| 编排后切换服务或删除素材，索引可能对应另一角色 | 前端附带预期后端、工作流和素材名称；不一致时要求重新编排 |
| 编辑时长、修改服务配置可能影响正在提交的请求 | 前端保存本次表单快照；后端固定本次 Provider、预算、步数和 LoRA |
| 时长与预算越界被偷偷裁剪 | 接口拒绝超界和非有限数值；错误能在模型运行前暴露 |
| 下载中断可能留下半截视频，空文件也可能标成成功 | 使用临时文件下载，完成且非空后发布；空输出标失败，失败下载不覆盖已有文件 |
| 旧记录列表标 I2V，详情却标 Ref2VA | 根据记录的后端与工作流优先显示，兼容旧元数据，不改写原视频或记录文件 |
| 旧提示词音频标记被误认为已提交的音频 | 详情说明记录中没有音频输入；保留原始提示词，便于核对历史行为 |

生成记录区分请求时长、计划节奏、像素预算及其来源。API 未消费的参数明确记录为未提交，不能拿这些请求字段当成实际成片尺寸或时长。
